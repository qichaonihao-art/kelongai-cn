# 镜头截取识别说明

## 处理方式

`clip-scene-detection.mjs` 负责 `/api/clips/detect-first-cut` 的镜头识别，视频范围和音频按镜头选范围共用结果。

- 仍只分析开头最多 60 秒，保留原帧率；画面先缩到宽 320 像素。
- 一次 FFmpeg 扫描同时输出场景变化分数和 16×16 RGB 帧摘要，不调用云端模型，也不保存额外预览文件。
- 结合相邻帧的变化基线、切点前后画面是否持续改变来判断，降低固定高阈值的漏检，并排除短暂闪光。
- 不再忽略开头 0.8 秒，也不再把相隔不足 0.6 秒的镜头直接合并。最开头不足 0.08 秒及紧邻的过渡帧仍做保护。
- 确认请求所需的切点后终止扫描。按源视频缓存切点和元数据；请求更多镜头时从最后切点前 0.3 秒继续，保留原始时间轴及可变帧率帧时间。
- 缓存有效期与源视频一致，通常为 15 分钟；清理源视频时清理对应缓存。同源并发请求共用正在进行的扫描。
- 没有确认切镜时，返回 `detected: false, shots: []` 和建议范围，界面不显示“已定位镜头”。

裁切编码参数、预览视频生成和播放逻辑沿用原实现；自动结束线仍落在切点前的相邻帧之间，避免带入下一镜头。前端视频和音频识别请求均检查视频及请求编号，避免过时结果覆盖当前范围。

## 回归验证

```bash
node --test legacy-project/clip-scene-detection.test.mjs
node legacy-project/test-clip-boundary.mjs
```

第一组覆盖开场短镜头、0.4 秒间隔的连续切镜、弱变化切镜、相近亮度的不同颜色、单帧/双帧闪光、短过渡、持续平移/缩放、可变帧率及非零起始时间，还检查缓存、续扫、并发和失败重试。

第二组使用隔离的后端与运行目录，完成真实上传、识别、截取和逐帧解码，检查 25/29.97/30/60fps、可变帧率、自动末帧、手动跨镜头选择、多镜头选择及未确认切点的接口提示。

## 本地速度对比（2026-10-18）

环境为本机 Node 24、FFmpeg 9.0.1。使用用户提供的学习素材目录中的 5 条 1080×1920 视频。预热后交替运行旧、新识别各 5 次，取中位数，测试时不并行运行其他视频测试。

| 素材 | 旧识别 | 新识别 |
| --- | ---: | ---: |
| 2.mp4 | 153ms | 156ms |
| 4.mp4 | 227ms | 231ms |
| 8.mp4 | 190ms | 187ms |
| 20.mp4 | 146ms | 150ms |
| 29.mp4 | 147ms | 150ms |

这是后端识别扫描耗时，不包含上传、网络、裁切或浏览器播放。额外开销在这批样本上为 -3～4ms；缓存读取为内存操作，避免重复解码。线上硬件、长视频和编码格式不同，绝对耗时会变化。

识别仍属于画面变化检测，长叠化或极相似画面的切换不保证全部命中，应保留预览和手动调线。
