# 文案转移

入口：创意创作 → 文案转移。前后端需一起部署，站点需启用 React 前端。

## 使用

原产品和目标产品左右对照填写：两边各有产品名称/形态、使用或安装方式、材质、结构/配件、适用场景；额外调整要求单独填写。名称和使用方式两边必填；原产品填写了材质、结构或场景时，目标产品也必须填写对应项。缺少对应信息的属性不由模型猜测。转换方案可在当前浏览器保存并再次选择。选择本地音频或视频文件，点击「批量处理」。每条先上传，再由 MediaKit 分离人声与音乐、阿里云 Paraformer 转写及区分说话人，最后由 DeepSeek Flash 对照两边属性返回局部替换项。原文未被替换的字符不经模型重写。

画面相同时保持默认选项，不需要上传图片。若画心内容变化，勾选「画心内容有变化」，上传本批次目标画心（必填），原画心选填；两张图片都上传时模型可直接对比。不属于同一画心的个别素材在队列中选择「单独上传图片」并指定自己的目标图，也可选择「画面相同，不传图」跳过批次图片。图片仅在分析阶段送入 DeepSeek Flash，作为核对原文中具体画面描述的依据；图片不会写进保存的产品转换方案。图片来自浏览器本地 JPG/PNG/WebP（原文件不超过 10 MB），发送前在浏览器内缩至最长边 1200 像素并转为 JPEG，服务端校验后直接转发给模型，不保存图片。使用图片的素材都会停在「待确认」，同事可看到本条使用的画心缩略图和逐句改动，然后确认再生成 MP3。

普通条目分析后直接生成；多说话人、句子长度变化大或音色样本太短的条目会标为「待确认」。试听原素材及每个人声样本后点击「确认这条文案」，再点击「生成已确认的 MP3」。未改动的原人声窗口保持原录音，修改的句子用对应说话人的阿里云克隆音色生成，要求新语音与原句时长差在 15% 内，背景音乐沿用原始时间轴。无 BGM 的素材只输出新旧人声。MP3 可以单独下载，也可将已完成音频打包下载为 tar.gz。

页面会显示当前文件、上传的实际传输百分比、服务端处理阶段和已用时间。分析与生成阶段的百分比是按完成的步骤显示，并非第三方 API 的实时完成比例；某一步等待较久时，已用时间仍持续更新。

## 依赖和边界

- 环境变量：`MEDIAKIT_API_KEY`、`ALIYUN_API_KEY`（或现有 DashScope ASR 密钥）、`DEEPSEEK_API_KEY`。模型分别使用现有阿里云声音克隆、`paraformer-v2` 和 `deepseek-flash`。密钥只在服务端读取。
- 单文件不超过 100 MB，音轨时长不超过 3 分钟，最多 120 个 ASR 句子。上传时要求服务器至少保留 1 GB 可用空间。后台分析和生成共用单工队列；上传及排队由打开的页面逐个推进。临时音轨、结果和预览计划在服务端保留约 2 小时，页面刷新或服务重启会丢失未完成的客户端队列或预览；已提交的后台任务可能继续运行。请在同一次操作中完成并下载。
- 没有可辨识的人声时间轴、多人重叠说话、说话人样本不足 3 秒或配音时长偏差过大的条目会失败并提示人工处理。BGM 分离质量取决于原素材；当前不保留分离出的独立音效轨。成品需要试听，尤其注意人声残留和句子接缝。
- 当前未实现服务器持久化批次，也未用真实计费 API 做线上端到端测试。部署前先用真实素材分别验证单人声、多人声、带 BGM 和无 BGM 四类。
- 图片识别和局部替换可能误判，带图任务必须人工核对。对同一批多个音视频，画心图片会随每条分析请求再次送给模型，模型图像 token 成本与处理条数有关；原音色/BGM 和时长校验依旧按原流程执行。
