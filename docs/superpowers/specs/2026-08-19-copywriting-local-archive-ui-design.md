# 文案创作页 · 本机挂画档案库 + 工作台式 UI 重构 设计文档

日期：2026-08-19
范围：`frontend-google-ui/src/pages/CopywritingPage.tsx`、`frontend-google-ui/src/lib/`（新增档案库模块）
不涉及后端改动。

## 背景与目标

1. 现状：挂画图片、档案、生成结果全部是内存态，退出页面即丢，第二天要用必须重新识别图片。
   团队一段时间集中做一款挂画，需要档案「一次确认、长期可用、主动删除才消失」。
2. 现状：页面为单列长滚动的三步流程，视觉平淡。需要更美观、更高效的桌面端工作台布局。

用户决策记录：
- 档案形态：**多档案库**（左侧列表可切换、可删除），不是只恢复上一次。
- 生成结果：**不自动存本机**（服务端文案库照旧，用于手动精选收藏）。
- 布局：**A · 工作台式**（左档案栏 + 右工作区），桌面端优先。
- 视觉：**② 宣纸墨韵**（宣纸米底 + 墨色文字 + 赭石点缀，仅限本页，不影响全站）。

## 一、本机挂画档案库

### 存储

新建 IndexedDB 库 `kelong-copy-paintings`（与现有 `kelong-upload-history` 分离），object store
`paintings`，keyPath `id`（自增）。记录结构：

```ts
interface SavedPainting {
  id: number;
  name: string;              // 档案名称（取 profile.name，无则「未命名挂画」）
  imageBlob: Blob;           // 压缩到最长边 720px 的 JPEG（复用 uploadHistory 的 canvas 压缩思路）
  profile: CopyProfile;      // 确认后的档案字段
  extraInfo: string;
  forbidden: string;
  createdAt: number;
  updatedAt: number;
}
```

新建模块 `src/lib/paintingArchive.ts`，接口：
`listPaintings() / getPainting(id) / savePainting(data) → upsert（有 id 更新，无 id 插入）/
deletePainting(id) / touchPainting(id)`（更新 updatedAt，用于「最近使用」排序）。
不设自动过期、不设数量上限（用户明确要求：除非主动删除，否则一直保留）。

### 行为规则

| 时机 | 动作 |
|---|---|
| 分析完成、点「确认档案」 | `savePainting` 自动写入；编辑后再确认则更新同一条 |
| 打开页面 | 列出全部档案，自动选中 `updatedAt` 最新的一个，恢复到可直接生成状态 |
| 点击档案项 | 恢复 imageThumb(objectURL)、profile、extraInfo、forbidden、profileConfirmed=true |
| 档案项 🗑 | 二次确认后 `deletePainting`；不影响服务端文案库 |
| 「＋ 新挂画」 | 右侧工作区切换到上传 → 分析 → 确认流程；已有生成结果此时清空 |

生成结果（10 条、仿写版本）不持久化，切换档案即清空——与用户决策一致。

### 边界情况

- IndexedDB 打开失败（隐私模式等）：档案栏显示空态 + 顶部小字提示「本机存储不可用，档案不会保留」，
  页面退化为现有纯内存行为，不阻塞任何功能。
- 存量为压缩图（几十 KB/张）：分析、生成不受影响；仅「重新识别」需原图时从上传历史重新选择。

## 二、布局与视觉

### 结构（桌面 ≥1024px）

```
┌──────────────┬─────────────────────────────────────┐
│ 档案栏(260px) │ 当前挂画条：缩略图+名称+档案要点chips   │
│ 固定随页滚动  │            +「编辑档案」「重新识别」    │
│              ├─────────────────────────────────────┤
│ ▣ 山河入梦 ●  │ [✨ 生成 10 条]      [生成中… 3/10]   │
│ ▢ 松鹤延年    │ ┌─────┐ ┌─────┐ ┌─────┐             │
│ ▢ 福字书法    │ │文案卡│ │文案卡│ │文案卡│  2~3列网格  │
│   (hover出🗑) │ └─────┘ └─────┘ └─────┘             │
│ ＋ 新挂画     │ ▸ 爆款仿写（折叠）                    │
│              │ ▸ 文案库（折叠）                      │
└──────────────┴─────────────────────────────────────┘
```

- 生成进度、异步轮询逻辑沿用上一轮已上线的实现，仅位置变化。
- 文案卡：方向徽标（稳定/探索 + 六方向）+ 字数徽标；钩子/正文/结尾三分区；hover 浮起；
  底部操作行：复制 / 入库 / 重生成 / 编辑（沿用现有逻辑与接口）。
- 仿写、文案库：默认折叠横条卡，点击展开（保留现有全部功能）。

### 视觉规范（仅本页）

| 用途 | 值 |
|---|---|
| 页面底色 | `#f7f3ea`（宣纸米） |
| 卡片面 | `#fffdf8` |
| 边框 | `#ddd3bd`，1px |
| 主文字 | `#2d2a26`（墨色） |
| 次文字 | `#8a8272` |
| 强调/主按钮 | `#9a3412`（赭石） |
| 圆角 | 卡片 4px、按钮 2px、徽标 2px |
| 选中态 | 档案项 1.5px 赭石描边；文案卡 hover 抬升 1px 阴影 |

实现方式：页面内局部样式（页面已有 tailwind，用任意值类名如 `bg-[#f7f3ea]` 即可，不引入全局主题）。

### 移动端降级（<1024px）

档案栏变为顶部横向缩略图滑条（单行、可横滑、末尾「＋」），其余上下堆叠，不做更多移动端专项优化。

## 三、测试与验收

- 无测试框架，沿用「一次性验证脚本 + 手动走查」方式：
  - 档案库模块：浏览器控制台驱动 upsert/list/delete/恢复，验证刷新后仍在。
  - 完整手动走查清单：
    1. 新挂画 → 分析 → 确认 → 刷新页面 → 档案自动选中、可直接生成（不再重新识别）。
    2. 两个档案互相切换，图片/档案/补充信息正确恢复。
    3. 删除档案有确认，删除后刷新不再出现。
    4. 生成 10 条全流程正常（含进度显示），复制/入库/重生成/编辑可用。
    5. 仿写、文案库折叠展开正常。
    6. 隐私模式下降级提示出现，功能不崩。
- `npx tsc --noEmit` 对改动文件无新增错误；`npm run lint` 无新增告警。

## 四、明确不做（YAGNI）

- 生成结果自动本机持久化（用户明确不要）。
- 档案同步到服务端 / 多设备共享。
- 档案自动过期、数量上限。
- 全站主题改造、深色模式。
